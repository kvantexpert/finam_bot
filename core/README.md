# Legacy `core/`

Каталог `core/` заморожен и больше не является целевым слоем архитектуры.

Новый код размещается только в `src/finam_bot/`.

## Зависимости, проверенные перед заморозкой

| Файл | Текущее использование | Решение |
|---|---|---|
| `arb_models.py` | Используется legacy `arb_calculator.py` / `arb_executor.py`; основной запуск также получает эти зависимости через `run_arbitrage.py` | Не удалять до миграции legacy entrypoint |
| `arb_connection.py` | Напрямую импортируется `run_arbitrage.py` | Оставить до миграции запуска |
| `arb_monitor.py` | Напрямую импортируется `run_arbitrage.py` | Оставить до миграции запуска |
| `arb_calculator.py` | Напрямую импортируется `run_arbitrage.py` | Оставить до миграции запуска |
| `arb_executor.py` | Напрямую импортируется `run_arbitrage.py` | Оставить до миграции запуска |
| `currency_monitor.py` | Напрямую импортируется `currency_monitor_cli.py` | Оставить до миграции CLI |

## Правило

`core/` не расширяем и не используем для нового кода.

Особенно запрещено переносить старую торговую логику в `src/finam_bot/` без переработки:

- `POINT = 0.0001`;
- магические коэффициенты размеров позиций;
- использование `CancelOrder` как закрытия исполненной позиции;
- последовательное открытие трёх ног без контроля fill/partial fill;
- автоматический выбор первого счёта;
- старую модель cross-треугольников без проверки реального набора инструментов.

## Следующий этап удаления

Сначала мигрировать `run_arbitrage.py` на `src/finam_bot/`, затем отдельно мигрировать `currency_monitor_cli.py`. После проверки импортов и тестов соответствующие файлы `core/` можно удалить отдельным коммитом.

## Этап 4 — новая модель арбитража

- [ ] представить рынок как граф инструментов/конвертаций;

## Этап 5 — risk engine

- [ ] max order notional;
- [ ] max exposure;
- [ ] max simultaneous cycles;
- [ ] daily loss limit;
- [ ] stale quote protection;
- [ ] price deviation protection;
- [ ] account-state checks;
- [ ] circuit breaker.

## Этап 6 — execution engine

Состояние заявки должно быть явным:

```text
planned
  ↓
submitted
  ↓
partially_filled ──► failed
  ↓
filled
```

Нужно реализовать:

- [ ] order plan;
- [ ] client order identity;
- [ ] order state machine;
- [ ] fill tracking;
- [ ] partial fills;
- [ ] rejected/cancelled orders;
- [ ] timeouts;
- [ ] idempotency;
- [ ] reconciliation.

## Этап 7 — unwind / close

- [ ] отличать cancel от close;
- [ ] определить фактическую позицию после каждой ноги;
- [ ] закрывать только фактическую экспозицию;
- [ ] обрабатывать частичный unwind;
- [ ] иметь аварийный сценарий при потере связи;
- [ ] журналировать результат unwind.

## Что делать после паузы

Если работа возобновляется после нескольких дней/недель:

1. прочитать `STATUS.md`;
2. проверить последний commit/PR;
3. выполнить smoke-тест текущего этапа;
4. посмотреть ближайший незакрытый пункт этого roadmap;
5. не перескакивать через этапы;
6. перед удалением legacy снова проверить зависимости.

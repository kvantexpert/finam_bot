# Структура репозитория Finam Bot

## Текущий этап

Репозиторий очищается поэтапно без изменения торговой логики.

```text
finam_bot/
├── core/                 # текущие модули стратегии, подключения и мониторинга
├── config/               # текущая конфигурация
├── diagnostics/          # диагностические проверки
├── FinamPy/              # vendored SDK; отдельно от собственного кода
├── Examples/             # примеры SDK, не production-код
├── data/                 # только входные/сохраняемые данные, runtime-данные не коммитятся
├── logs/                 # runtime-логи, не коммитятся
├── docs/                 # документация и решения по архитектуре
├── arbitrage_*.py        # legacy-реализации; не использовать для live-торговли
├── run_arbitrage.py      # текущая точка запуска legacy-контура
├── currency_monitor_cli.py
└── requirements.txt
```

## Целевая структура

После отдельного этапа миграции собственный код будет перенесён в пакет:

```text
src/finam_bot/
├── api/                  # Finam API adapter
├── market/               # инструменты и котировки
├── strategy/             # расчёт арбитражных возможностей
├── risk/                 # лимиты и circuit breaker
├── execution/            # заявки, fills и unwind
├── monitoring/           # мониторинг рынка
└── config.py
```

Миграция в `src/` намеренно не выполняется одновременно с cleanup: сначала фиксируем состав проекта и удаляем артефакты, затем меняем импортную структуру.

## Правила

1. Реальные торговые заявки не выполняются автоматически из диагностических команд.
2. `CancelOrder` не считается закрытием уже исполненной позиции.
3. Legacy-арбитраж не считается безопасным live execution engine.
4. Runtime-логи, `__pycache__`, virtualenv, build и локальные отчёты не хранятся в Git.
5. Изменения торговой логики делаются отдельными коммитами от структурного cleanup.
